# api_tests

Интеграционные тесты `ghreport` на pytest. Служба запускается отдельным процессом и проверяется как чёрный ящик.

## Запуск

```sh
python3 -m pip install -r api_tests/requirements.txt
cd service && go build -o ghreport .
GHREPORT_BIN="$PWD/ghreport" python3 -m pytest ../api_tests -q
```

Для запуска из корня:

```sh
GHREPORT_BIN="$PWD/service/ghreport" python3 -m pytest api_tests -q
```

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `GHREPORT_BIN` | Обязательный абсолютный путь к собранной службе |
| `GITHUB_TOKEN` | Необязательный токен, передаётся службе |
| `GITHUB_API_BASE_URL` | Переопределяется на встроенный сервер-заглушку, чтобы тесты были детерминированными |

Набор поднимает локальный HTTP-сервер, соответствующий контракту GitHub REST API, и передаёт его адрес службе. Тесты не обращаются во внешнюю сеть и только читают данные.

## Покрытие

- пагинация по `Link`, `--limit`, отсутствие повторов;
- фильтрация pull request и `--since`;
- условные запросы и кэш между запусками;
- `429` с `Retry-After`;
- `401`, `404`, `all_failed`, повреждённый JSON, код 2 для аргументов;
- схема отчёта и сортировка;
- поля `--trace` и отсутствие `Authorization`.
